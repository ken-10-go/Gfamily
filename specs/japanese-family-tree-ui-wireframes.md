# 日本風サーバーレス家系図アプリ UI/UXワイヤーフレーム ＆ 画面設計仕様書 (v1)

本ドキュメントは、AIコーディングエージェント（Claude Code等）が本システムを構成するFlutter (iOS/Android/Web) フロントエンド画面を完全に自律実装・検証できるように設計された、厳密で詳細なUI/UXワイヤーフレームおよび画面遷移・配置仕様書である。

本仕様は、発行済みの以下の仕様書と完全にデータモデル・セキュリティ仕様レベルで連動している：
*   **PRD (v4)**: `japanese-family-tree-requirements-v4.md`
*   **Firestoreスキーマ定義 (v3)**: `japanese-family-tree-db-schema-v3.md`
*   **E2EEセキュリティ仕様 (v3)**: `japanese-family-tree-security-specs-v3.md`
*   **システムアーキテクチャ (v3)**: `japanese-family-tree-architecture-v3.md`

---

## 1. 画面構成マップと画面遷移フロー

本システムは以下の5つの主要画面およびコンポーネントで構成される。

```
                       [ 0. アプリ起動 / 認証 ]
                                  │
                                  ▼
                     [ 3. E2EEパスフレーズ入力 ] ◀── (初回またはセッション切れ)
                                  │ (鍵生成完了/復号OK)
                                  ▼
                    ┌───────────────────────────┐
                    │ 1. メイン家系図ビュー     │ ◀── (トグルで合同・単家切替)
                    └─────┬───────────────┬─────┘
                          │               │
      (人物タップ)         │               │ (ツリー管理タップ)
                          ▼               ▼
    [ 2. 人物詳細ポップアップ ]    [ 4. 複数ツリー・マージ管理 ]
     (人物票・戒名・お墓登録)       (ダブル・ハンドシェイク申請/承認)
                          │
                          ▼
             [ 5. 行事・回忌通知設定 ]
             (お盆・お彼岸・命日・長寿祝)
```


#### UIコンポーネント & インタラクション仕様

1.  **ツリーセレクター (Top Segmented Control)**:
    *   `Tree_id` に紐づく現在選択可能な単一ツリー、または `TreeBridges` が有効な場合の「両家合同（Combined View）」を切り替える。
    *   「両家合同」を選択した場合、Firestoreから他家の `isDeceased == true`（故人）のPerson情報および `Relationships` 情報のみをバックエンドより透過的にロードし、合成ツリーを描画する。
2.  **表示モード切替 (Layout Toggle)**:
    *   **縦書き表示（折本・毛筆風）**: 画面を横スクロールさせ、ご先祖様を右から左へ、世代を上から下（またはその逆）へと日本の伝統的な折本家系図フォーマットで描画。
    *   **横書き表示**: デジタル描画で一般的な階層ツリー表示。
3.  **接続線（系譜線）のスタイル**:
    *   **婚姻（夫婦関係）**: 二重実線（`======`）
    *   **実親子関係**: 一本実線（`──────`）
    *   **養親子関係**: 破線または細二重破線（`= = = =`）
4.  **フォーカス中心表示（すいすい表示）**:
    *   任意の人物カードをダブルタップすると、その人物をスクリーンの中央に配置し、その人物から上下3世代（高祖父母、玄孫まで）のカードのみをアニメーションで抽出し、画面を整理する（画面の小さなスマホでの複雑化を回避）。

#### UIコンポーネント & インタラクション仕様

1.  **和暦・西暦のスマートコンバータ**:

    *   「月日不明」チェックボックスをONにすると、`birthMonth` / `birthDay` カラムを NULL に設定して画面上には「〇〇年〇月吉日」または「〇〇年 不明」として保存することを許容。
2.  **E2EEインジケータ（🔒マーク）**:
    *   「本籍地」「住所」「エピソード」の入力欄には左側に 🔒（錠前マーク）を表示し、この項目がクラウドに送信される前に端末側でローカル暗号化されることを明示し、ユーザーに安心感を与える。
3.  **旧字体・変体仮名のサポート警告**:
    *   氏名入力エリアのフォーかく時に、プレースホルダーまたは注意書きとして「※戸籍に記載の旧字体（例: 邊、 𠮷）の入力に対応しています」という文言を表示。

1.  **PBKDF2 鍵導出プレグレスバー**:

2.  **復旧バックアップPDFエクスポート (Disaster Recovery)**:
    *   ボタンを押すと、入力されたパスフレーズ、およびE2EEの概念、復旧手順、QRコードが美しくレイアウトされた紙印刷用の「復旧カードPDF」をその場で生成してデバイスの印刷ダイアログを起動する。

#### UIコンポーネント & インタラクション仕様

1.  **提携コードジェネレータ**:
    *   「提携コード発行」をタップすると、Firestoreの `trees/{treeId}` ドキュメントに紐づく使い捨ての一時パスコードを発行、親族にLINEやメールで簡単送信できる共有リンクを展開する。
2.  **承認時の警告ダイアログ**:
    *   「提携を承認する」をタップした際、「相手のツリー管理者に、こちらの山田家系の『故人（死亡済みの人物）』の情報のみが共有されます。生存者の機微な情報（本籍地、住所、連絡先等）や暗号化されたデータが相手に渡ることはありません」という警告ポップアップを表示して同意を求める。
3.  **リアルタイムステータス変化**:
    *   承認が完了すると、非同期で `tree_bridges` テーブルにレコードが追加され、メイン家系図ビューに即座に相手の家（佐藤家など）への接続アンカーが描画される。

## 3. Flutter (Dart) 実装向け画面コンポーネント構造案

AIエージェントがすぐにFlutterソースコードを生成できるよう、推奨する Widget 構成ツリーを示す。

```
lib/
├── main.dart                      # アプリ起動、Firebase初期化、Auth監視
├── models/                        # db-schema-v3.mdに準拠したモデル層
├── services/                      # E2EE暗号化、Firestore、Functions連携
└── views/
    ├── screens/
    │   ├── login_screen.dart      # Firebase Auth ログイン・新規登録
    │   ├── passphrase_screen.dart # E2EEパスフレーズ入力・PBKDF2鍵導出
    │   ├── tree_view_screen.dart  # メイン家系図描画（Canvas / CustomPainter）
    │   ├── tree_bridge_screen.dart# A家B家マージ・提携コード管理画面
    │   └── settings_screen.dart   # 通知、法要基準、エクスポート設定
    └── widgets/
        ├── person_card_widget.dart# 最小限情報を表示する常時表示カード
        ├── detail_modal_sheet.dart# タップで立ち上がる詳細人物票
        └── lineage_painter.dart   # 夫婦(======), 親子(──)を動的描画するPainter
```

本仕様に沿ってFlutter/Firebaseの実装を進めることで、日本の家制度、伝統的供養の文化、そしてオンラインならではのリアルタイム性が完全に統合された、極めて完成度の高いデジタル家系図システムが完成する。
