# バックアップと、安全まわりの手順

アプリの外（Firebase コンソール・端末のコマンド）で行う作業をまとめる。
コードだけでは完結しないものだけを書いてある。

## 1. 手で取るバックアップ

更新はときどきなので、**節目で手動**で十分。ゴミ箱は人物1人ずつしか戻せないので、
「丸ごと戻せる控え」をこれで持つ。

### 置き場所をいちど作る（初回だけ）

```bash
gcloud auth login
gcloud config set project family-505409
gcloud storage buckets create gs://family-505409-backup --location=asia-northeast1
```

### 取る（やりたいときに1行）

```bash
gcloud firestore export gs://family-505409-backup/$(date +%Y%m%d) --project family-505409
```

数十秒で終わる。`gcloud storage ls gs://family-505409-backup/` で一覧が見える。

### 戻す

```bash
gcloud firestore import gs://family-505409-backup/20261029 --project family-505409
```

⚠ **import は同じ ID の文書を上書きする**（消えた文書は戻るが、
取ったあとに増えた文書はそのまま残る）。戻す前に、いまの状態を一度 export しておくこと。

### もうひとつの保険（PITR）

Firebase コンソール → Firestore → バックアップ で
**ポイントインタイム リカバリ**を入れると、直近7日のどの時点へでも戻せる。
操作ミスや乗っ取りの直後に効く。少し課金が増える（データ量に比例、家族規模なら些少）。

## 2. App Check を効かせる（bot よけ）

画面側の組み込みは済んでいる（`src/lib/firebase.ts`）。鍵を入れるまでは何も起きない。

1. Firebase コンソール → **App Check** → アプリを登録 → **reCAPTCHA v3**
   （サイトキーとシークレットが出る。シークレットはコンソールに貼るだけで、リポジトリには置かない）
2. GitHub → リポジトリの Settings → Secrets and variables → **Variables** に
   `VITE_RECAPTCHA_SITE_KEY` を追加（サイトキーは公開前提の値なので Variables でよい）
3. push すると、その鍵の入ったアプリが本番へ出る
4. コンソールの App Check で**しばらく「未強制」のまま様子を見る**（リクエストの何割に印が
   付いているかが出る）。ほぼ 100% になってから **Firestore と Cloud Functions を「強制」に切り替える**

⚠ 鍵を入れる前に強制へ切り替えると、**全員がアプリを開けなくなる**。順番を守ること。
手元の開発（`.env` に鍵なし）とエミュレータでは App Check は動かないようにしてある。

## 3. Authentication まわりの設定

- Firebase コンソール → Authentication → 設定 → **ユーザーアクションの保護**
  （メール列挙の防止）を有効にしておく
- 同 → **承認済みドメイン** は、本番の Hosting ドメインだけに絞る
  （プレビュー用の `*.web.app` を外すと、プレビューでログインできなくなる点に注意）
- 自己サインアップは止めたまま（`disabledUserSignup`）。登録は招待リンク経由だけ

## 4. 招待リンクの運用

- 共通リンクには**使用上限**（既定20人）が付く。超えると自動的に使えなくなる
- 配り終えたら、メンバー画面の「発行済みの招待」から**取り消す**
- 有効日数は短いほどよい（既定7日）

## 5. GitHub

push がそのまま本番へ出る作りなので、**リポジトリへの書き込み権限＝本番への書き込み権限**。
アカウントの2要素認証を有効にしておくこと。
